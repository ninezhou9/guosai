# 支撑材料使用说明

本材料只保留各问最终版本，内部按以下两类组织：

- `代码/`：问题一、问题二、问题三、问题四、时间对齐、绘图。
- `结果/`：五份最终result工作簿，各问汇总、明细和核验记录，以及跨日补算记录。

`AI使用说明.docx`说明AI使用范围。`结果/问题一`至`问题四`中的敏感性分析、模型选择和诊断文件是最终计算的支撑记录。

## 代码入口

| 内容 | 入口 |
| --- | --- |
| 第一问 | `代码/问题一/q1_solution.py` |
| 第二问 | `代码/问题二/run_fresh.py` |
| 第三问 | `代码/问题三/run_q3.py`、`deliver_q3.py` |
| 第四问 | `代码/问题四/run.py`、`deliver.py`、`audit.py` |
| 时间对齐 | `代码/时间对齐/` |
| 数据图 | `代码/绘图/run_all_figures.m`、`figA_netload_forecast_update.py` |

源码副本仅适配简化后的目录路径，求解函数、参数和计算方法保持不变。复现时，把题目提供的原始`基础数据/`目录放在本目录下，按第一至四问顺序生成预测与调度缓存。各问程序及其`results/`缓存沿用相邻目录关系，新增计算结果不替代根部`结果/`中的已核验答案。

在本目录运行：

```powershell
python 代码/问题一/q1_solution.py
python 代码/问题二/run_fresh.py
python 代码/问题三/run_q3.py
python 代码/问题三/deliver_q3.py
```

第四问在`代码/问题四/`中依次运行`run.py`、`deliver.py`、`audit.py`。全新运行需使用空输出目录；完整模型缓存未打包，只有现成答案与支撑明细时不能直接跳过前面的计算。

得到完整缓存后，依次执行`代码/时间对齐/boundary_prediction.py forecast`、`q4`、`q1`、`q3`，再执行同目录的`prepare_templates.py`、`refill_templates.mjs fill`（Node）和`verify_templates.py`。回填结果生成在`tmp/result_template_refill_20260913/filled/`。

Python依赖包括NumPy、SciPy、LightGBM、openpyxl、Matplotlib；预测图另需pandas。Excel回填依赖Node和`@oai/artifact-tool`，MATLAB用于三张数据图；运行时与依赖库未打包。

## 时间口径

输入时标按区间结束时刻解释。模板首段00:10—00:20使用模型第二段，末段使用次日00:00—00:10计划。第一问将给定光伏预测延续一个日周期后调用原求解器；第三问和4-3在年末沿用最后一次有效预报，并以此前7天同一时刻的预报均值延拓缺失时段。

结果表合计按其显示窗口计算；各问汇总和明细仍按自然日统计，两种窗口的费用不可直接混用。每行末段来自次日零点产生的计划；4-2和4-3年末跨日费用采用预测电价。详细假设和数值来源见`结果/跨日补算/`。

附录中的核心源码与本目录对应文件一致。Word已完成内容、源码和结构核对；按用户确认省略实际分页检查，分页仍未验证。
